# Parent Control — аудит і внесені виправлення

Версія пакета: **1.6 / versionCode 7** (попередня версія в наданому архіві: 1.5 / versionCode 6).

## Що змінено

### Android: гібридне застосування політик
- `DeviceCapabilities.kt` визначає Device Owner, Device Admin і стан Accessibility через системні API.
- У Device Owner режимі `PolicyEnforcer` застосовує блокування пакетів через `DevicePolicyManager.setPackagesSuspended()`; зміни політики зберігаються між запусками.
- У звичайному режимі збережено Accessibility-блокування як fallback. Статус відсутньої Accessibility-служби передається серверу.
- `GuardService` більше не виконує мережеву синхронізацію; він відповідає за локальну реакцію на запуск програм і повторно читає політику з SharedPreferences, щоб не працювати зі застарілою копією.
- `BootReceiver` і `AdminReceiver` повторно застосовують політику після старту/розблокування; WorkManager запускає синхронізацію незалежно від Activity.

### Синхронізація і команди
- Додано WorkManager: одноразова синхронізація після підключення/відкриття та періодичний запуск із мінімальним інтервалом Android 15 хвилин.
- Сервер більше не позначає команди виконаними в момент видачі. Команди мають ID і стани `pending`, `delivered`, `done`; непідтверджені команди повторно доставляються після 60-секундної lease.
- Android надсилає ID і результат команди у наступній синхронізації та зберігає локальний список уже оброблених ID для захисту від повторного виконання.
- У вебпанелі повідомлення більше не обіцяють виконання за 20 секунд; показується, що команда чекає наступної синхронізації.

### Оновлення APK
- Оновлення завантажується у тимчасовий файл до відкриття PackageInstaller-сесії.
- Перевіряються SHA-256, applicationId, versionCode і відповідність підпису встановленому APK.
- Обробляються `STATUS_PENDING_USER_ACTION`, `STATUS_SUCCESS` і помилки встановлення.
- `update_tried` фіксується лише після успішного встановлення; завислий стан інсталяції скидається після 30 хвилин.
- Для self-update на Android 12+ за наявності дозволу встановлення задається `USER_ACTION_NOT_REQUIRED`; додано `REQUEST_INSTALL_PACKAGES` і `UPDATE_PACKAGES_WITHOUT_USER_ACTION`. Система все одно може повернути `STATUS_PENDING_USER_ACTION`, тому цей callback обробляється; беззвучність не заявляється як гарантована для всіх конфігурацій.
- Версію збільшено до 7, щоб пакет можна було встановити поверх наданої версії 6 за умови незмінного ключа підпису.

### Блокування хостів
- VPN тепер оголошує локальний DNS через `addDnsServer()` і маршрутизує його до віртуального IPv4 resolver. Це усуває основну помилку попередньої конфігурації, коли DNS не був оголошений VPN як DNS-сервер.
- Upstream DNS-запити відправляються через `protect()`-сокет, щоб не зациклити їх у VPN.
- Додано нормалізацію доменів (lowercase, IDN, кінцева крапка), оновлення upstream DNS при зміні мережі та foreground notification для VPN service.

### Сервер і вебпанель
- Додано міграції SQLite для нових полів і таблиці команд без видалення попередніх даних.
- Додано звіт про режим Device Owner, Accessibility і помилки застосування політики.
- Завантаження APK записується атомарно, обмежене 200 MiB, сервер обчислює SHA-256.
- Сервер не приймає адміністративний доступ із порожнім ключем або `change-me`; Windows setup/start перевіряють ключ.
- Виправлено дубльований рядок денного звіту в `server/main.py`.

## Що не підтверджено

- Повний `gradle assembleDebug` не запускався: у середовищі немає Gradle executable та Android SDK. Отже, Kotlin/Android компіляція цього пакета ще не підтверджена.
- Немає фізичного Android-пристрою/емулятора для перевірки Device Owner provisioning, встановлення APK, VPN і поведінки після reboot/Doze.
- WorkManager має системний мінімум 15 хвилин і не є push-механізмом. Без Firebase Cloud Messaging віддалені команди не гарантовано миттєві; фактичний час контролює Android.
- DNS реалізація в цьому пакеті підтримує лише IPv4 UDP DNS. TCP DNS, IPv6 DNS, DNS-over-TLS, DNS-over-HTTPS і прямі IP-з'єднання не блокуються цим фільтром. Це не повноцінний firewall.
- Звичайний режим залежить від увімкненої Accessibility-служби для блокування окремих програм. Без Device Owner сторонній застосунок не має системних повноважень призупиняти пакети.

## Перед розгортанням

1. Перевірити GitHub Actions `gradle assembleDebug --no-daemon`.
2. Переконатися, що APK має `applicationId=ua.parentcontrol.agent`, `versionCode=7`, `versionName=1.6` і підписаний тим самим ключем, що й установлені версії.
3. Завантажити саме цей APK у вебпанель з `version_code=7` та `version_name=1.6`.
4. На тестовому пристрої перевірити спочатку звичайний режим, потім Device Owner на окремому тестовому/скинутому пристрої.
5. Не вважати DNS-фільтр повним захистом від обходу; перевірити DoH/DoT і IPv6 окремо.

**Ключ підпису:** `android/keystore/debug.keystore` залишено незмінним для сумісності оновлення. Це debug-ключ, не production-grade секрет. Якщо репозиторій публічний, ключ вважати скомпрометованим; не змінювати його без окремого плану міграції підпису, інакше встановлені APK не приймуть оновлення поверх.
